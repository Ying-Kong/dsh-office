## dsh-office 0.1.2 — 现在装得上、也真的会挂载

The Python core is unchanged since 0.1.0. This release only fixes how the DSH
plugin is packaged and mounted.

> **Use this version.** `0.1.0` throws at load (missing `output.render`) and
> `0.1.1` installs as a plain dependency that nothing mounts. Details below.

### Fixed in this release

- **The tarball now mounts itself.** `0.1.0`/`0.1.1` declared `dsh.bundle.entry`,
  a field the loader never reads — `app-boot` only honours `dsh.bundle.patch`.
  The package was therefore treated as a plain dependency: no patch row, no
  mount, the three tools never appeared in a session.
  `node/cordis.patch.yml` now ships one row (`id: dsh-office`) and
  `package.json` declares `dsh.bundle.patch`, so `dsh plugin add` appends the
  package to `dsh.profile.bundles` and **enables it automatically**.
- `files` includes `cordis.patch.yml`, so `npm pack` really ships it
  (5 files, 5.1 kB).

Carried over from 0.1.1: `defineTool` output schema/render, profile-based peer
resolution for linked installs, and `engines.dsh >=0.2.0-0` instead of `*`
(which does not match the host's `0.2.1-rc.2`).

### Install

```bash
git clone https://github.com/Ying-Kong/dsh-office && cd dsh-office
git checkout v0.1.2

python3 -m venv .venv && .venv/bin/pip install -e "python/[dev]"

cd node && npm pack                                   # dsh-office-plugin-0.1.2.tgz
dsh plugin --profile web add ./dsh-office-plugin-0.1.2.tgz

export DSH_OFFICE_PYTHON=$PWD/../../.venv/bin/python    # absolute path to the venv
dsh web
```

Upgrading from a broken install:

```bash
dsh plugin --profile web remove @dsh-office/plugin
dsh plugin --profile web add ./dsh-office-plugin-0.1.2.tgz
```

### Verify it mounted

```bash
grep dsh-office ~/.dsh/profiles/web/package.json        # listed under dsh.profile.bundles
dsh --profile web --dump-config | grep -A2 "id: dsh-office"
```

Then, in a session: ask the model to run `office_extract` on
`fixtures/templates/report.docx`.

### Compatibility

| | |
|---|---|
| Tested on | DSH `0.2.1-rc.2`, Node `24.16.0` |
| Declares | `engines.dsh >=0.2.0-0`, peer `@deepseek-ai/dsh-tools >=0.2.0-0` |
| Registers | `office_extract`, `office_fill`, `office_verify`; no services, no global state |
| Python | ≥ 3.10, `python-docx` + `click` + `jsonschema` |

### Known limitations

Pagination is not asserted (engine-dependent), theme fonts and document grids
resolve to `null`, legacy `.doc` is rejected, Excel is planned and PowerPoint is
a non-goal — see [`docs/limitations.md`](https://github.com/Ying-Kong/dsh-office/blob/main/docs/limitations.md).
